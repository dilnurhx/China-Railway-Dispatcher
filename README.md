## 二、怎么玩

### 基本流程（两站一致）

1. 左侧面板点一行列车 → 画布上高亮该车。
2. 点一条**绿色空闲股道** → 接车，列车开始进站动画。
3. 车停稳后，点股道上的那列车 → 放行，它开出咽喉。

### 三个关键概念

- **停靠 / 通过**：面板每行标了这一趟是「停靠」还是「通过」。通过车（紫色）自动横穿咽喉，**不占股道、不用你操作**。
- **跨场 / 本场**（重庆北专属）：面板标了这趟车是否跨越场区，方便你判断该往哪个场排。
- **咽喉占用**：同时进出的列车上限。超了会被拒绝，日志里会提示"咽喉已满"。

### 控制条（右上角）

| 控件 | 作用 |
|---|---|
| ⏸ / ▶ | 暂停 / 继续 |
| 1x 2x 4x 8x | 时间倍速 |
| 🔊 | 全局静音 |
| ♫ 滑块 | BGM 音量 |
| ◈ 滑块 | 音效音量 |

音量设置存 localStorage，下次打开保持。

## 四、数据来源与边界

- 时刻表取自 **2026 年二季度运行图**（2026-04-15 起执行），来源为 12306 / 公开时刻表 / 铁路官方发布。
- **是抽样，不是全图。** 重庆北 26Q2 全图约 399 对，公开可逐列核对的车次收录 117 趟；沙坪坝 57 趟。
- 场别（进哪个场）、股道（停哪条线）**由玩家自行安排**，程序不做自动分配——这是游戏设定，不是缺陷。
- 咽喉并行为简化模型（按列计数，不追踪具体道岔进路），用于制造冲突压力，不对应真实信号联锁。

## 五、音频说明

- 全部由 **Web Audio API 实时合成**，零音频文件、零外链、零版权风险。
- BGM 为五声音阶随机游走 + 和弦垫 + 低频脉冲，**密度和亮度随繁忙度变化**（车多则收紧）。
- 8 种音效：选中、接车、停稳、发车、即将来车、非法操作、晚点、跑图完成。
- **首次必须点一下页面才会出声**——浏览器自动播放策略限制，点完即正常。

## 七、已知限制 / 可讨论项

- ~~重庆北信息密度高，29 线需滚动~~ → **已修**：画布高度自适应窗口，1920×1080 / 1600×900 下 29 线全部可见无需滚动；窗口过矮时兜底滚动（行距不低于 25px）。
- **节奏偏快**：重庆北 1:6 倍率下车流密集，8x 基本只能看不能操作。
- **无存档**：刷新即重开，没有中途保存。
- **无计分卡**：有正点/晚点计数和完成趟数，但没有结算页和评级。
- **通过车不参与冲突**：目前只是视觉横穿，不占咽喉，比真实情况宽松。

## 八、修改指引

游戏逻辑全部在文件末尾的 `<script>` 里，按 `/* ===== XXX ===== */` 分区注释，主要区块：

- `TRAINS_DATA` — 时刻表数据（改车次只动这里）
- `buildTracks()` — 站场股道定义
- `classify()` — 列车分类判定
- `tryAssignTrack()` / `tryDepart()` — 接车 / 放行
- `renderTimetable()` — 左侧时刻表面板
- `drawTrains()` — 画布渲染
- `Audio` 模块（`AU`）— 音频总控

改完保存、刷新浏览器即可生效，无需构建。
